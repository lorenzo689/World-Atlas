# Kafka outage drill · 17 October 2026

Environment: local Windows development machine, Docker Compose PostgreSQL 17 and Kafka 4.2.1, Spring Boot 4.1.1. Command: `./scripts/drill-outbox.ps1` with the application already running. The script created a uniquely named guest through `/api/auth/guest` while Kafka was stopped; this writes a `user.registered` event into the transactional outbox.

| Observation | Result |
| --- | --- |
| 15 seconds after the guest request, Kafka stopped | Outbox row present, unsent, 0 completed retries |
| Broker restart | Kafka started through Compose; the local broker took several minutes to become ready under a 4 GiB Docker memory limit |
| Recovery | The same row had `sent_at` set after 4 delivery attempts; script exited successfully |

The drill shows durability and eventual delivery for one real local outage. It does not measure a 30-day delivery SLO or prove recovery under every broker failure. The relay's capped retry schedule and exhausted-event admin flow are documented in [ADR 0002](adr/0002-outbox-recovery.md). The runbook and proposed SLO are in [PORTFOLIO.md](PORTFOLIO.md).
